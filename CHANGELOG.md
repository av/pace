# Changelog

Notable changes per release, newest first. Also published as [GitHub releases](https://github.com/av/pace/releases).

## Unreleased

### New features

- **Scriptable search output: `pace search --json` / `--limit`** — `pace search --json --limit 5 starred:yes seen:no` makes the terminal search machine-friendly: `--json` emits the hits as one JSON document (the `/api/search` response shape — `query`/`count`/`items` with each item's `panel` — plus `starred` and `seen` booleans per item, since the CLI reads the state marks anyway), always parseable even at zero matches, while the stderr summary keeps stdout clean for piping into `jq`. `--limit N` (`-n N`) caps the hits with the exact semantics of the API's `?limit=` (integer 1-500, same error message on invalid values); the default stays the newest 50.
- **Search from the terminal: `pace search`** — `pace search rust seen:no` runs the dashboard's search over the stored database straight from the shell, no server required — grep for your feeds. It speaks the exact `/api/search` grammar (whitespace-separated terms AND-matched case-insensitively over title/url/source/summary/body, plus the `starred:yes|no`, `seen:yes|no`, and `panel:<id>` operators), returns the newest 50 matches, and marks each hit's state in the first column — `★` starred, `·` read — with the URL indented beneath so results stay scannable and pipeable. The summary (`search: N matches for "…"`) goes to stderr, matches to stdout; a query with no matches exits 0 quietly, while a typo'd operator (`seen:ys`) is the same clear error the API returns. The config is only loaded when a `panel:` operator needs resolving (id or display name, exactly like `?panel=`), and `--config`/`--preset`/`--chdir` work as usual.
- **Search panel scoping inside the query: `panel:<id>`** — `/api/search` and `/api/search.rss` now accept a `panel:<id>` operator inside `q` itself, completing the shared grammar with the dashboard's `/` filter bar: a bar query like `rust seen:no panel:hacker-news` pastes into `?q=` verbatim and means the same thing server-side. The operator resolves panels exactly like `?panel=` (id or display name, unknown panel a 404, the "all recent items" pseudo-panel spanning everything), is case-insensitive on the operator name with last-wins on repeats, and echoes normalized in the JSON `query` field and the RSS channel title so scoped saved-search feeds stay distinguishable in a reader. Giving both `?panel=` and a `panel:` operator is an unambiguous 400 rather than a silent preference, a bare `panel:` is a 400 naming the form, and a `panel:`-only query points you at `/api/panels/<id>` — that feed already exists.
- **Filter bar panel scoping: `panel:<id>`** — the dashboard's `/` filter bar gains a third operator: a `panel:<id>` token (the panel's `data-panel-id`, the same id the refresh route and `/api/search`'s `?panel=` resolve) limits the filter to that one panel, combining with text terms and the `starred:`/`seen:` state operators — `rust seen:no panel:hacker-news` is "unread Rust stories on the Hacker News panel". Case-insensitive with last-wins on repeats; a bare `panel:` stays a literal text term like other invalid operator values. The **RSS** saved-search link maps the operator onto the endpoint's `?panel=` parameter so the scoped query is subscribable exactly as typed (a `panel:`-only query offers no link — per-panel feeds already exist at `/api/panels/<id>.rss`). Progressive enhancement as ever: static exports and no-JS pages are untouched.
- **Filter bar state operators: `starred:` / `seen:`** — the dashboard's `/` filter bar now speaks the same grammar as `/api/search`: `starred:yes`/`starred:no` and `seen:yes`/`seen:no` tokens filter the rendered items by state instead of matching text, combine with plain terms and each other (`rust seen:no` — unread Rust stories; `starred:yes` alone — your pins), are case-insensitive with last-wins on repeats, and re-filter live as you star or mark items so the view never goes stale mid-session. The bar's **RSS** saved-search link carries the normalized operators too, so an operator query is subscribable server-side exactly as typed — and since the client can't return a 400, a typo'd value (`starred:ys`) simply stays a literal text term. Progressive enhancement as ever: static exports and no-JS pages are untouched.
- **Search by read state: `seen:yes` / `seen:no`** — `/api/search` and `/api/search.rss` queries gain a seen-state operator alongside the star one: `q=rust seen:no` finds only the Rust stories you haven't read yet, `seen:yes` only what you have, and the operators combine (`starred:yes seen:no` — pinned but unread). It resolves through the same dedup identity seen marks are saved under, so a story read on any panel counts as read everywhere; an operator-only query is valid, a typo'd value (`seen:ys`) is a clear 400 naming the valid forms, and saved-search RSS feeds echo the normalized operator in their channel title — making "unread rust stories" a subscribable feed.
- **Search by star state: `starred:yes` / `starred:no`** — `/api/search` and `/api/search.rss` queries gain a star-state operator: `q=rust starred:yes` finds only starred matches, `starred:no` only unstarred ones, and `q=starred:yes` alone lists the whole starred set as JSON (complementing `/api/star.rss`). The operator is case-insensitive, resolves through the same dedup identity stars are saved under (a story starred on any panel matches everywhere), combines with `?panel=` and `?limit=` as usual, and a typo'd value (`starred:ys`) is a clear 400 naming the valid forms rather than a silent literal text match. Saved-search RSS feeds echo the normalized operator in their channel title, so a "starred rust stories" feed stays distinguishable in a reader.
- **Starred items as a feed: `GET /api/star.rss`** — the reading list built with the `s` key is now itself a subscribable RSS 2.0 feed: every starred item, most recently starred first, so your pinned stories can follow you into a regular feed reader, a read-it-later service, or any tool that speaks RSS — and double as a portable export of the list. Star keys resolve back to stored items through the same dedup identity they were saved under, so each story appears once no matter how many panels carry a copy; the newest star mark stamps the channel's `lastBuildDate` while every entry keeps its own story timestamp, `?limit=` shares the panel endpoints' validation, and a star whose item has aged out of retention simply drops from the feed until the story returns. Read-only like the other feed endpoints, `server.base_path` respected.
- **Starred-only view: `Shift+S`** — press `Shift+S` (or click the toolbar ★ button) and the dashboard shows only your starred items: every unstarred item disappears, panels with nothing starred dim, and keyboard navigation skips exactly what's hidden — turning your pins into a focused reading list. The toolbar button's label carries how many starred items the view is showing, the choice is remembered per browser (`localStorage`, like the theme and hide-seen toggles), and pressing `Shift+S` again brings everything back. Client-side progressive enhancement as ever: static exports and no-JS pages are untouched.
- **Starred items** — press `s` (or click the ★ button revealed on item hover, always visible on touch screens) to star a story you want to keep: it gets an accent star after its title, stays at full opacity even once read, and hide-seen mode never hides it — a page-wide `Shift+X` or a panel-level `hide_seen: true` clears everything you're done with while your pinned stories stay put. Stars persist server-side (`GET`/`POST /api/star`, same cross-site guard as the other state-changing endpoints) keyed by the item's dedup identity, so a story starred on one panel is starred on every panel and across browsers, and unlike seen marks they survive retention pruning — a deliberate keep-mark, not read state. Client-injected as ever: static exports and no-JS pages never render the buttons or classes.
- **Notify item field selection: `{{items_json_array:…}}`** — the structured-items placeholder in `format: template` bodies now takes a field selection: `{{items_json_array:title,url,score}}` substitutes the matched items as a JSON array of objects narrowed to just the listed fields, in the listed order, instead of the full seven-field item shape. The practical win is dropping the bulky `summary` (which can carry a whole LLM-written digest per item) from deliveries whose receiver never shows it, but any subset works — a bot that only wants `title` and `url` gets exactly that. Fields come from the item shape (`title`, `url`, `source`, `panel`, `timestamp`, `score`, `summary`); a typo'd or empty selection fails `pace config check` naming the valid fields, bare `{{items_json_array}}` keeps sending everything, and like all presentation it never touches the delivery ledger.
- **Offline banner retry button** — the offline banner now carries a "Retry now" button that re-attempts a live load with one click. The service worker is strictly network-first, so once the connection is back a retry replaces the cached copy with a fresh render — and because the browser's `online`/`offline` events miss some failure modes (captive portals, a down pace host on a live link), the button gives the reader a direct way to try again without hunting for the browser reload. While still offline, a retry harmlessly re-serves the cached render, banner and all.
- **Offline banner** — while the browser is offline, the dashboard shows a banner at the top of the page ("Offline — showing the last saved render from … UTC"), so the service worker's cached copy is never mistaken for live data. The banner names the render's own timestamp (stamped as `data-updated-at` on the page body), appears immediately when a page loads offline or the connection later drops, is announced to screen readers as a status change, and disappears the moment the network returns. Client-injected as ever: static exports and no-JS pages never render it.
- **Offline last-render viewing** — the dashboard now registers a lightweight service worker (`GET /sw.js`), so when the server is unreachable — laptop offline, pace host down, phone in a tunnel — a reload shows the last-rendered dashboard instead of a browser error page. Strictly network-first: the live server always wins and every successful response refreshes the cache; only a failed fetch falls back to the cached copy, with navigations falling back to the cached dashboard page. The app shell (page, stylesheet, client module, icon, manifest) is precached under `server.base_path`, and together with the web app manifest this satisfies Chrome's PWA installability criteria, upgrading "Add to Home screen" to the full install prompt. Progressive enhancement as ever: unsupported browsers and static exports are untouched.
- **Per-panel hide-seen override** — layout panels gain their own `hide_seen: true`/`false`, overriding the page-wide hide-seen mode (`Shift+X` / `server.hide_seen`) in either direction: a hand-picked "to-read list" panel with `hide_seen: false` keeps showing its read items while the toggle clears the rest of the page, and a high-volume firehose panel with `hide_seen: true` shows only unread items no matter the toggle (dimming to "all caught up" when nothing unread remains). The layout stamps `data-hide-seen="on"/"off"` on the panel element; CSS and the client module check the item's panel before the page-wide mode, keyboard navigation skips exactly what is hidden, and the toolbar's hidden-count badge counts only items the toggle actually governs. Non-boolean values fail `pace config check`; panels without the field, and static/no-JS pages, behave exactly as before.
- **Start on unread items: `server.hide_seen`** — set `server: { hide_seen: true }` and the dashboard opens with hide-seen mode already on, so a fresh visit shows only what you haven't read yet instead of making you press `Shift+X` first. The server stamps `data-hide-seen="on"` on the page body and the client applies it on load — but only when the visitor has no stored choice: toggling `Shift+X` now persists explicitly in both directions, so turning hide-seen off sticks across reloads even against the config default. Non-boolean values fail `pace config check`; static exports carry no seen state and never render the stamp.
- **Per-panel mark-on-open override** — layout panels gain their own `auto_mark_seen: true`/`false`, overriding the page-wide `server.auto_mark_seen` default in either direction: a "to-read list" panel can keep fully manual read state (`false`) while the rest of the dashboard marks items seen on open, or one panel can re-enable mark-on-open (`true`) on an otherwise-manual dashboard. The layout stamps `data-auto-seen="on"/"off"` on the panel element and the client module checks the item's panel before the body, so panels without the field keep following the server setting exactly as before. Non-boolean values fail `pace config check`; static/no-JS pages are unaffected as ever.
- **Installable as an app** — the dashboard now serves a web app manifest (`GET /manifest.webmanifest`, linked from the page head), so Android's "Add to Home screen", desktop Chrome/Edge's "Install", and iOS Safari's share sheet install pace as a standalone home-screen app: its own window without browser chrome, the pace monogram as the app icon (reusing the served `/favicon.svg`), and a dark splash/window color matching the palette's theme-color metas. `id`/`start_url`/`scope` live under `server.base_path`, so multiple pace instances behind one origin install as distinct apps. Static exports stay self-contained files and never link a manifest.
- **Mobile browser chrome matches the theme** — the dashboard now declares `<meta name="theme-color">`, so the parts of the browser outside the page — Android/iOS address bar, tab strip, task-switcher card — are tinted with the palette's background instead of a default white or gray. A media-attribute pair (light + dark) follows the OS preference with no JavaScript, covering static exports and no-JS visitors, and on interactive pages the client module pins both metas to the active theme on every change — the `t` toggle, the OS follow, a live OS appearance flip — so the chrome never disagrees with the page. A test keeps the meta colors in lockstep with the stylesheet's `--bg-base` tokens.
- **Structured notify items: `{{items_json_array}}`** — `format: template` bodies gain a structural placeholder beyond the `{{name_json}}` twins: `{{items_json_array}}` substitutes the matched items as a real JSON array of item objects — the exact `NotifyPayloadItem` shape the `json` format sends (`title`, `url`, `source`, `panel`, `timestamp`, `score`, `summary`) — so a receiver that wants structured items (a custom endpoint, a card-building bot, anything that iterates) gets machine-readable data inside an otherwise hand-shaped envelope instead of one preformatted text blob. Valid only in the top-level `template` (per-item shaping is what `item_template` is for — which, being presentation for `{{items}}`, never affects the array), it passes `pace config check`, appears in unknown-placeholder error lists, and like all presentation never touches the delivery ledger.
- **Native browser UI matches the theme** — the stylesheet now declares CSS `color-scheme`, so the parts of the page the browser paints itself — form controls, classic scrollbars, the canvas behind overscroll/rubber-banding — render dark on the dark theme and light on the light theme instead of always defaulting to the browser's light chrome. It follows every way a theme gets picked: the `t` toggle, the OS `prefers-color-scheme` follow on interactive pages, and static exports' media-query palette — all pure CSS, no JavaScript involved, and a test pins the declaration to each theme block.
- **JSON-safe notify placeholders** — every `format: template` placeholder, in both `template` and `item_template`, gains a `{{name_json}}` twin that substitutes a JSON literal instead of raw text: strings escaped and quoted, `{{matched_json}}` a bare number, `{{score_json}}` a number or `null` when the item is unscored. A rule targeting a JSON-envelope service (Google Chat, Teams, a custom receiver) can now write `{"text": {{headline_json}}}` and stay valid JSON no matter what quotes or newlines the first feed title carries — previously the raw placeholders made hand-built JSON bodies silently breakable by content. The twins pass `pace config check`, unknown-placeholder errors list them among the valid set, and like everything presentational they never touch the delivery ledger.
- **Favicon unread count** — the favicon's unread dot now renders the number itself while the distinct-story count is a single digit (1–9), so a pinned or narrow tab tells you not just *that* something is waiting but *how much*; at 10+ a two-digit number would be illegible at favicon size, so the dot goes plain exactly as before. Same count semantics as the `(N) pace` tab-title prefix, updated live through every mark, and the served `/favicon.svg` and static-export icons stay the plain monogram — the digit only ever appears through the client-side unread swap.
- **Mark-on-open opt-out** — `server: { auto_mark_seen: false }` disables the automatic mark-seen when an item's title link is opened, for people who treat unread as a to-read list rather than a have-seen list: read state becomes fully manual, changed only by `x`, `a`, and the injected mark-seen buttons. The server stamps `data-auto-seen="off"` on the dashboard body so the dependency-free client module simply skips its open handler — everything else (dimming, unread counts, hide-seen, the favicon dot) works unchanged. Defaults to `true`, non-boolean values fail `pace config check`, and static/no-JS pages are unaffected as ever.
- **Per-item templating for notify templates** — `format: template` rules gain an optional `item_template`: a per-item line rendered once for every delivered item and joined into `{{items}}` in place of the default bullet list, with `{{title}}`, `{{url}}`, `{{source}}`, `{{score}}` (empty when the item is unscored), and `{{meta}}` ("source" / "source, score N") substituted per item and the "…and N more" overflow line kept. This lets the item list itself speak the receiving service's syntax — Slack-style `<url|title>` links inside a JSON envelope, Teams/Google Chat card lines, CSV-ish rows — instead of being stuck with the fixed plain-text bullets. Typo'd per-item placeholders fail `pace config check` up front with the valid list, `item_template` outside `format: template` is rejected, `pace notify test` renders it too, and like everything presentational it never touches the delivery ledger.
- **Static exports follow the OS light/dark preference** — pages produced by `pace share export` now honor `prefers-color-scheme`: a viewer whose OS is set to light appearance gets the exact same light palette (tokens and source-badge colors alike) the interactive theme toggle uses, straight from CSS with no JavaScript involved. Scoped strictly to exported pages — interactive dashboards keep being governed by the `t` toggle and its localStorage/OS-preference logic, and dark-preferring viewers of an export see the dark theme exactly as before. A palette-parity test keeps the export media block and the interactive light theme from ever drifting apart.
- **Favicon for everyone: `/favicon.svg` and static exports** — the pace monogram is now a real served asset (`GET /favicon.svg`, cacheable SVG, `base_path` respected) and the server renders the `<link rel="icon">` itself, so no-JS visitors, bookmarks, and anything that fetches `/favicon.svg` directly get an icon without JavaScript; static exports embed the same icon as a self-contained `data:` URL. The client module keeps doing what it did — swapping the link's href for the unread-dot rendering as you read — from the exact same SVG markup, so the two can never drift.
- **Notify template format** — `notify:` rules gain `format: template`, a generic escape hatch when none of the built-in presets (json, ntfy, discord, slack) fits the receiving service: the rule's own `template` string becomes the delivery body, with `{{rule}}`, `{{matched}}`, `{{headline}}`, and `{{items}}` (the ntfy-style plain-text bullet list, overflow folded into "…and N more") substituted per delivery. Typo'd placeholders fail `pace config check` up front instead of shipping literally forever, and — uniquely for this format — a custom `Content-Type` header is allowed, since the user rather than a preset owns the body (so a template can be a JSON envelope for services like Google Chat or Teams). `pace notify test` renders it too, and like `format`/`headers`, editing a template never re-notifies: the delivery ledger ignores presentation.
- **Filter button in the toolbar** — the dashboard's top-corner toolbar gains a fourth button that opens (and closes) the `/` item filter bar, making live filtering reachable on touch screens and by mouse — previously the filter was keyboard-only, effectively invisible to tablet and phone users. Clicking focuses the filter input just like pressing `/`, a second click closes and clears it like `Escape`, and everything downstream (live matching, the match count, the saved-search RSS link) works unchanged. Client-injected by the same dependency-free progressive-enhancement module; static exports and no-JS browsers are unaffected.
- **Favicon with an unread dot** — the dashboard now has a favicon at all (a pace monogram, injected client-side as an inline SVG), and it earns its keep: while any read-tracked story is unseen the icon gains a dot in its corner, disappearing once you're caught up — so even a pinned or narrow tab that can't show the `(N) pace` title still signals unread items. The dot follows the exact same distinct-story count as the tab-title prefix and updates live through every mark (`x`, `a`, `Enter`/click auto-mark-on-open, mouse buttons). Client-injected by the same dependency-free progressive-enhancement module; static exports and no-JS browsers are unaffected. (The CSP's `img-src` now also allows `data:` URIs to let the icon through.)
- **Unread total in the browser-tab title** — the dashboard's tab title now carries the page's unread count, email style (`(12) pace`), so a background tab shows at a glance whether anything new is waiting. The count tracks distinct stories (a story duplicated across panels counts once, matching how one `x` mark clears its twins everywhere) and updates live with every mark — `x`, `a`, `Enter`/click auto-mark-on-open, and the injected mouse buttons all keep it current; once everything is read the plain server-rendered title returns untouched. Client-side only, by the same dependency-free progressive-enhancement module; static exports and no-JS browsers keep their normal title.
- **Per-panel unread counts** — every panel header now shows a small badge next to the title counting how many of the panel's items you haven't marked seen yet, updating live with every mark — `x`, `a`, `Enter`/click auto-mark-on-open, and the injected mouse buttons all keep it current. The badge disappears entirely once a panel is fully caught up (and never appears on panels without read-tracking), so headers stay clean; hovering it spells the count out as "N unread". Client-injected by the same dependency-free progressive-enhancement module; static exports and no-JS browsers are unaffected.
- **Notify custom headers** — `notify:` rules gain an optional `headers` map sent with every webhook delivery, so authenticated endpoints work without a proxy in between: protected ntfy topics (`Authorization: Bearer ${NTFY_TOKEN}` with the config's usual `${VAR}` env expansion keeping tokens out of the file), shared-secret headers, API keys. Custom headers merge over the delivery format's own headers, winning case-insensitively — except `Content-Type`, which stays owned by the `format` preset and is rejected by `pace config check`, along with malformed header names and newline-carrying values. `pace notify test` sends them too, so auth problems surface during setup. Headers are transport-only: like `format` and `name`, changing them (rotating a token) never re-notifies.
- **Hidden-item count badge** — while hide-seen mode (`Shift+X`) is on, the toolbar's hide-seen button now shows how many seen items the mode is currently hiding, updating live as items are marked or unmarked; the count is mirrored into the button's accessible label ("Show seen items (N hidden)") so screen readers hear it too, and the badge disappears entirely when the mode is off or nothing is hidden. Client-injected by the same dependency-free progressive-enhancement module; static exports and no-JS browsers are unaffected.
- **Collapse all panels** — pressing `Shift+C` on the dashboard collapses every panel down to its header row at once, turning the page into a compact overview; pressing it again when everything is collapsed expands them all back. Panels that were individually collapsed with `c` join in either direction (collapse-all unless *every* panel already is), the result persists per browser through the same localStorage state as `c`, and collapsed states remembered for other dashboards on the same origin are left alone. Keyboard focus caught inside a collapsing panel lands on that panel's refresh button so navigation continues. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers are unaffected.
- **Opening an item marks it read** — activating an item's title link (`Enter` on the focused item, a click, or a middle-click into a new tab) now automatically marks the item seen through the same server-persisted `/api/seen` state as the `x` key, so read-tracking keeps itself up to date as you browse instead of requiring a separate keystroke per story. Duplicates of the story on other panels dim along with it, re-opening an already-seen item never flips it back to unread, and `x` still un-marks anything you want to keep. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers are unaffected.
- **Top-corner toolbar** — the dashboard's page-wide keyboard actions are now clickable too: a small toolbar fixed in the top-right corner carries a theme toggle (`t`), a hide/show-seen-items toggle (`Shift+X`, highlighted with the accent while active), and a help button (`?`). Together with the earlier per-panel and per-item buttons this makes every dashboard action reachable by mouse or touch alone. Labels always name the action a click will perform (they follow theme restores and even live OS appearance changes), state syncs through the exact same code paths as the keys, and the toolbar is injected client-side by the same dependency-free progressive-enhancement module — static exports and no-JS browsers never render it.
- **Notify delivery format presets** — `notify:` rules gain an optional `format` field so a webhook can point straight at a popular service without a translation shim: `ntfy` (plain-text body with ntfy's `X-Title`/`X-Click` headers), `discord` (webhook markdown `content`, kept under Discord's 2000-character limit by folding overflow items into an "…and N more" line instead of truncating mid-link), `slack` (incoming-webhook mrkdwn `text` with clickable links), or the default `json` (the raw payload, unchanged). Titles are escaped per service, format is validated by `pace config check`, and `pace notify test` sends its sample in each rule's format so you see exactly what the service will render. Presentation only: switching formats never re-notifies or changes what a rule matches.
- **`pace notify test`** — verify webhook notification endpoints before a real high-signal item arrives: the command sends a sample delivery (the exact payload shape of real deliveries, clearly marked as a test in its title and summary, with the rule's criteria spelled out) to every configured `notify:` rule, or just one with `pace notify test <rule-name>`. Results are reported per rule and the command exits non-zero when any delivery fails; the at-most-once delivery ledger is never touched, so testing can't swallow future notifications. `--config`/`--preset`/`--chdir` work as usual.
- **The theme follows your OS preference** — until you pick a theme with `t`, the dashboard now follows the operating system's light/dark preference (`prefers-color-scheme`), live: flipping the OS appearance retints an open dashboard. The first `t` press pins an explicit choice (light *or* dark) in localStorage, which then wins on every future visit — so existing dashboards where `t` was already used keep behaving exactly as before. Static exports and no-JS browsers keep the dark default.
- **Subscribe to a search from the filter bar** — the dashboard's `/` filter bar now shows an **RSS** link whenever the query is non-empty, pointing at `/api/search.rss` for exactly the terms typed (normalized the same way the bar matches them, respecting `server.base_path`). One click turns a filter you keep reaching for into a saved-search feed in your reader; the link hides again when the query is cleared. Client-injected by the same dependency-free progressive-enhancement module; static exports and no-JS browsers are unaffected.
- **Webhook notifications** — a top-level `notify:` config list pushes high-signal items to any webhook as they arrive: after every refresh, new items on the refreshed panels matching a rule's `min_score` (llm-rank / keyword-score threshold) and/or `keywords` (case-insensitive, title/body/summary) are POSTed as JSON — rule label, total match count, and the newest 20 matches with title/url/source/panel/timestamp/score/summary. Rules can be scoped to specific panel ids. A SQLite ledger keyed by the item's dedup identity guarantees at-most-once delivery per rule (cross-panel duplicates and re-fetches never re-notify), failed deliveries retry on the next refresh, and ledger entries age out with `server.retention_days`. Validated by `pace config check` like the rest of the config.
- **Mouse affordances for collapse and seen state** — the dashboard's collapse and read-tracking actions are now clickable, not just keyable: every panel header gains a collapse chevron (rotates when collapsed) and a mark-all-seen button next to the refresh button, and hovering an item reveals a mark-seen button in its top-right corner (always visible on touch screens, which have no hover). Each button drives exactly the same logic as its keyboard twin (`c` / `a` / `x`) with synced ARIA state (`aria-expanded`, `aria-pressed`, action-reflecting labels), and the per-item buttons stay out of the Tab order since keyboard users already have `x`. All buttons are injected client-side by the same dependency-free progressive-enhancement module; static exports and no-JS browsers never render them.
- **Mark whole panel read** — pressing `a` on the dashboard marks every item in the focused panel seen at once (or unmarks them all when everything already is), pairing with `x` (single item) and `Shift+X` (hide seen). `/api/seen` now also accepts a bulk body — `POST {"keys": [...], "seen": true}` with up to 500 keys — applied atomically in one SQLite transaction, with the same same-origin guard and per-key validation as single marks. Duplicates of a story on other panels dim along with it, and in hide-seen mode focus moves on to the next panel so keyboard flow continues. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers are unaffected.
- **Hide seen items** — pressing `Shift+X` on the dashboard hides every item marked seen (`x`) across all panels, turning the dashboard into an unread-only view; pressing it again brings them back. `j`/`k` navigation skips hidden items, panels left with nothing unread are dimmed to read as "all caught up", and marking the focused item seen while the mode is on moves focus to the panel's next remaining item. The choice is remembered per browser in localStorage and restored on the next visit. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers are unaffected.
- **Seen/read item state** — pressing `x` on the dashboard marks the focused item as seen (dimmed, back to full opacity on hover/focus) and pressing it again unmarks it. State is persisted server-side in SQLite via a new `/api/seen` endpoint (`GET` lists keys, same-origin `POST {key, seen}` sets one), keyed by the item's dedup identity so duplicates of a story across panels share one mark, it survives refreshes, and it is shared across every browser that opens the dashboard. Marks age out with `server.retention_days` once no stored item still carries the key. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers are unaffected.
- **Saved-search RSS feeds** — `GET /api/search.rss?q=terms` renders the server-side search as an RSS 2.0 feed, so any query becomes a subscribable saved search in a regular feed reader: new matches from any configured source appear in the feed. Same AND term semantics, `?panel=<id-or-name>` scoping, and `?limit=` cap as `/api/search`; the channel is titled after the query (`pace search: rust wasm`), `lastBuildDate` tracks the newest hit, and the feed's self link keeps the query string since that is the feed's identity.

The entire palette (backgrounds, text, borders, accent, source badges) is driven by CSS custom properties, so the light theme is a single `:root[data-theme="light"]` override block. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers keep the dark default.
- **`pace export` (OPML export)** — the inverse of `pace import`: exports the feed URLs from the active config (`--config`/`--preset` supported) as an OPML 2.0 file any feed reader can import — one folder per `rss` or `podcast` adapter, one outline per URL. Prints to stdout or writes to a file (`pace export feeds.opml`); non-feed adapters and duplicate URLs are skipped with a warning, and the output is validated to round-trip through `pace import`.
- **Panel collapse** — pressing `c` collapses the focused panel down to its header row (and expands it again); collapsed panels are remembered per browser in localStorage and restored on the next visit, keyed by panel id via a new `data-panel-id` attribute. `h`/`l` navigation still lands on a collapsed panel's refresh button so it stays reachable. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers are unaffected.
- **Dashboard item filter** — pressing `/` opens a filter bar that live-filters items across every panel (case-insensitive, all terms must match). `Enter` jumps to the first match, `Escape` clears and closes, panels with no matches are dimmed, and `j`/`k` navigation skips filtered-out items. Same dependency-free progressive-enhancement module as keyboard navigation; static exports and no-JS browsers are unaffected.

## v0.6.6

### BREAKING: one-way database schema migration

The items table primary key changed from `id` to a composite `(id, panel_id)`, so a source feeding multiple panels no longer "steals" items between them — each panel now keeps its own copy. Existing databases are migrated automatically and transactionally on first startup (including pre-rename legacy schemas).

**The migration is one-way.** Older pace versions fail against a migrated database with SQLite error `ON CONFLICT clause does not match`. To downgrade, delete `data/pace.db` (or restore a backup). 

### New features

- **`server.retention_days`** — configurable item retention (default 30 days; `0` disables pruning). Pruning runs at startup and every 24h; invalid values are rejected at config validation.
- **`llm.timeout_seconds`** — configurable LLM completion timeout (default 120s). A hung provider (e.g. a stalled local Ollama) can no longer block a panel's refresh slot forever.
- **Richer `/health` endpoint** — was a hardcoded `{status:"ok"}`; now reports overall `ok|degraded` plus per-source `status` (`ok|failing|pending`), `lastError` (cleared on recovery), `lastSuccessAt`/`lastFailureAt`, `lastDurationMs`, and `lastItemCount`. Documented in README.
- **Refresh feedback in the UI** — skipped refreshes redirect to a status banner (`?skipped=`), and browser-initiated refresh failures redirect to an error banner (`?failed=`) instead of a dead text/plain 502 page (non-browser clients still get 502).
- **Graceful shutdown** — SIGTERM/SIGINT now stops the scheduler, stops the HTTP listener, drains in-flight refreshes (10s timeout), then closes the database; also cleans up properly when the port is already in use (friendly `EADDRINUSE` message instead of a raw stack trace).
- **Bookmarks improvements** — stable url-hash item ids (summaries/scores survive reorders), first-seen timestamps (new links surface on top, existing ones age naturally), and stale rows are pruned when entries are removed from config. Duplicate bookmark entries that collapse to one row now produce a config warning.
- **Config warnings** — new warnings for panels mixing a pipeline with its upstream adapter, and an accurate shared-source warning.
- CLI: `--preset` combined with `--config` is now rejected; unknown flags, missing option values, and stray positionals are rejected on all subcommands instead of being silently ignored.

### Bug fixes

#### Scheduler / data integrity
- Serialized per-panel writes to prevent lost updates when concurrent refreshes touch a shared panel.
- Pipelines no longer re-transform their own output on shared panels (which duplicated LLM calls and grew ids unboundedly); adapter-level transforms no longer wipe pipeline output; enriched pipeline copies now win read-side dedup over raw items.
- Deduplicated pipeline input across shared read-key panels and same-id copies (count-limited transforms no longer fill slots with duplicates).
- Canonicalized `fetched_at` format (mixed ISO/SQLite formats broke "last refreshed", dedup tie-breaks, and same-day pruning).
- Future-dated feed items are clamped at ingestion (5-min tolerance) so clock-skewed feeds no longer pin to the top of panels forever.
- `refresh_interval` is clamped to the 32-bit timer maximum (huge values previously wrapped into a ~1ms tight refresh loop).

#### Adapters and feed parsing
- Feed XML: numeric text nodes are no longer coerced (`<title>1984</title>` rendered "(untitled)"); date elements with attributes parse correctly; non-page atom link rels (enclosure/self/…) are no longer used as item URLs.
- HTML entity decoding rewritten single-pass: astral code points (emoji) decode correctly, invalid refs pass through, escaped entities no longer double-decode; ~45 typographic/currency entities added.
- Malformed JSON elements no longer crash whole fetches: reddit, stackexchange, lemmy, mastodon, npm, devto, lobsters, github-releases now validate/degrade per element.
